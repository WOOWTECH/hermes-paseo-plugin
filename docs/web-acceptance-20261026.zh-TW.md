# Paseo Web 實測：2026-10-26

本輪在官方 `https://app.paseo.sh` 操作真實瀏覽器，連接專用 Hermes 測試服務。文字對話、配對、模型／模式切換、中止、兩裝置並行與重連通過。附件首次測試因缺少檔案工具失敗；使用者核准後已啟用工具並通過原生讀寫測試。**模型讀取附件及歸檔還原後的續聊仍待帳號額度恢復後重測**，不能列為全功能正式上線通過。

## 環境與判定方法

- 官方 Web 顯示 **0.13.0**；插件管理的 daemon **0.11.2**；Hermes **0.22.5**；插件 **0.1.4-rc.2**；PaaS chart **0.4.0**。
- 桌面 Chromium 1440×1050；另建沒有 Paseo 儲存資料的瀏覽器 context，以 390×844、mobile／touch 模擬測試配對與續聊。這不是實體 iOS Safari 或 Android 裝置測試。
- 真實模型：`openai-codex:gpt-6.1-sol`、`openai-codex:gpt-6-luna`。畫面有 15 個模型項目，不代表所有模型均已驗收；未啟用的本機模型不列為可用。
- 建立、送出、切換、取消、改名、搜尋、歸檔及還原均從 Web 操作。使用正式 SDK 讀回模式、模型、agent 狀態與 assistant 訊息作交叉核對；不以畫面中的使用者訊息或模型清單代替真正回覆。
- 模型測試使用隨機代碼。續聊 prompt 不重複提供答案；兩個並行對話的回覆逐字核對各自代碼。原始對話、配對連結、瀏覽器登入資料及截圖留在私人證據目錄，不上傳公開 repo。

首輪收尾確認 daemon running／reachable、兩個容器 Ready、各零重啟、cgroup OOM kill 為 0，已安裝插件原始碼沒有改動。當時 ACP 只有 `hermes_paseo`；後續授權與變更見下節。模型帳號已回報額度耗盡，主機健康不代表模型請求可完成。

## 已找到的問題與處理

### 附件需要實際檔案工具

已檢查正在執行的 daemon 0.11.2：`uploaded_file` 轉換為名稱、主機路徑、MIME、大小的文字提示，並未將內容內嵌為 ACP resource。Hermes 收到提示後，需要能讀取該主機路徑。

首次測試時，profile 保留先前的小模型工具限制，原生配置解析的 ACP 工具集只有 `hermes_paseo`。這解釋了「上傳成功，但模型不能讀取」；不是配對未完成。模型曾嘗試代查，產生的測試子代理已按工具結果的精確 ID 歸檔。

使用者後續明確核准原生 `file` 工具集，已只將專用測試 profile 的 ACP 設為 `[file, hermes_paseo]`。原生 `file` 含 `read_file`、`write_file`、`patch`、`search_files`，受服務帳戶權限約束，不保證限制在目前工作區。這是指定服務的已授權配置，插件安裝／更新本身繼續保留使用者原有工具範圍。

### 核准後的配置與原生驗證

2026-10-26 05:47 UTC 保存配置前，以 600 權限備份原設定；使用同版 Hermes 原生工具選單的保存函式。讀回實際 ACP 工具集為 `file`、`hermes_paseo`，CLI 工具與 ACP 以外的配置逐項比對不變。

使用已部署 Hermes 的 ACP `SessionManager` 建立真正的 AIAgent，使用獨立臨時資料庫，沒有送出模型 prompt。實際載入 10 個工具，包括 4 個檔案工具與 6 個 Paseo 工具。透過原生已註冊 handler，成功讀出先前 Web 上傳的同一份 62 位元組附件；再於唯一臨時目錄完成 write_file → read_file → patch → search_files，逐次核對實際檔案內容與搜尋結果。臨時資料庫及檔案均已清除。

配置後重新開啟 Hermes 插件頁與官方 Paseo Web，確認服務 reachable、原配對可用、主機 Online、Hermes provider 可見；此段也未送出模型 prompt。

這項證據涵蓋新 ACP 實例的工具載入與原生檔案操作。模型選擇工具、呼叫工具及產生正確附件回覆，仍須額度恢復後在 Paseo Web 重測；不把原生 handler 成功代替模型驗收。

### 重連期間可見輸入框不代表已可送出

重新整理後立即送出曾顯示 Host is not connected，草稿仍在。等主機 Overview 為 Online 後重送成功。明確切斷傳輸也確認此保護與重送行為；沒有把第一次「只設 navigator offline、但 WebSocket 未確定中斷」的測試當作斷線驗收。

### 模型額度與一般錯誤提示

還原後的續聊實際收到供應商 HTTP 429，接著顯示 `Internal error: admitted_turn_failed`。底層供應商訊息已確認為訂閱額度不足，不能只看最後一則一般錯誤就判定主機或配對失效。記錄後停止新增模型請求。重置時間是供應商當時的回報，不是本插件的保證。

### 測試腳本修正與範圍

手機的 New workspace 收在側邊選單；工作區改名後，無障礙按鈕名稱還包含狀態；附件移除按鈕需先 hover；斷線提示可能是 Host is not connected 或 Transport not connected。初版 runner 在這些條件等待失敗，調整為實際 UI 後重測通過，沒有把這些腳本失敗列為產品故障。

本輪未重新驗收語音／聽寫、圖片理解、外部 Issue／PR 整合、排程與 heartbeat、所有 provider、所有權限提示、完整檔案編輯流程、跨瀏覽器及實體手機。Web／daemon 的版本差異提示仍存在，未為消除提示而更換已固定的 runtime。長期負載、整機／整卷災難復原與 OAuth 長期更新，仍屬 [整體待驗範圍](validation.md)。

## 重測順序

1. 本測試服務已完成授權、設定備份、ACP 選擇及其他設定不變的核對；其他部署仍須按自己的管理權限完成此步驟。
2. 模型帳號額度恢復後，在新 Web 對話附加含全新隨機代碼的文字檔，要求模型讀出檔內代碼；確認真正 read_file／assistant 結果，避免代查形成額外對話。
3. 歸檔並分別還原工作區與 agent，不在 prompt 重複提供答案，確認能續聊記住前文。
4. 歸檔本次測試 agent／工作區並確認沒有背景生成或終端殘留。只有以上都實測成功後，才更新對應未通過／被阻擋項目。
